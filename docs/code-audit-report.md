# HallowBadges-Ghost correctness audit

Date: 2026-10-26. Scope: editable hardware, saved netlist, BOM, manufacturing exports, firmware example and project documentation. This is a source audit and compilation check, not a new hardware qualification.

## Fixed

- **Firmware build failure:** The former README example called `tiny_srandom` and `tiny_random`, which are undefined in MicroCore 2.5.2. Reproduced compiler errors before the change. The [standalone sketch](../firmware/HallowBadges/HallowBadges.ino#L3) now uses `PIN_PB0`, `randomSeed` and `random`; it compiles without warnings for the configuration in the README.
- **Malformed board outline:** The original PCB had zero-length `Edge.Cuts` segments at lines 494 and 3978, with matching duplicates in [the custom footprint](../HallowBadges.pretty/ghost-outline.kicad_mod). Removed exactly those two lines from each file. Every remaining byte of the board and footprint is unchanged, including copper, pads, tracks, nonzero contour segments, coordinates and net assignments.
- **Missing custom library registration:** Added [fp-lib-table](../fp-lib-table#L1) with a project-relative `HallowBadges` library. DRC now resolves the supplied custom footprint, eliminating that missing-library warning. Standard footprint and 3D libraries remain external dependencies.
- **Missing legacy symbol cache:** Restored all seven complete symbol definitions in [HallowBadges-cache.lib](../HallowBadges-cache.lib) from KiCad 5.1.7, commit `bf475af94877e8fd9cf80e667578ff61835e02bb`. DEF/F1 names are adapted for legacy cache lookup and aliases expanded; all remaining source fields, pins and drawing commands are retained. [Provenance](../THIRD_PARTY.md) and the byte-identical upstream [licence](../LICENSE-KiCad.md) are included. The missing cache caused the earlier load failure; the legacy schematic format itself loads in nightly KiCad once its symbols are supplied.

## Hardware findings requiring review before fabrication

- **High — assembly specification is incomplete.** [BOM lines 2–10](../HallowBadges-BOM.csv#L2) and the schematic retain generic resistor and LED values. No values were inferred from photos. BT1's BOM names a Keystone 3002 footprint but links a BC-2003 datasheet; the PCB's 3D references name a 3008 holder and CR1225 cell. Confirm the actual holder and cell against the physical PCB; renders and datasheet links are not a reliable procurement specification.
- **High — power sources are directly connected.** [Netlist VCC](../HallowBadges.net#L296) connects BT1 pin 1, J1 pin 1 and U1 pin 8 without source isolation. README instructions now require removing the coin cell before external/ISP power. No charging or power-selection circuitry has been added.
- **Important — schematic and PCB component sets differ.** [H1/H2 schematic symbols](../HallowBadges.sch#L102), [netlist components](../HallowBadges.net#L25) and BOM entries exist, but neither mounting-hole footprint is on the PCB. The PCB contains ten electrical components plus the custom artwork footprint. Their intended inclusion cannot be established from the repository, so neither holes nor symbols were silently added or removed.
- **Important — no local supply-decoupling capacitor is specified.** The schematic, netlist, BOM and PCB component sets contain no capacitor. [Microchip AVR042](https://www.microchip.com/content/dam/mchp/documents/MCU08/ApplicationNotes/ApplicationNotes/atmel-2521-avr-hardware-design-considerations_applicationnote_avr042.pdf) recommends local supply decoupling. Address this in a reviewed hardware revision with new manufacturing outputs and physical validation.
- **Important — copper artwork is close to the outline.** Nightly DRC applies a 0.5000 mm edge-clearance constraint and measures 0.3806 mm between the custom footprint's F.Cu polygon and Edge.Cuts. The equivalent original KiCad 5 constraint is not established; artwork was not moved and rules were not relaxed. Confirm the intended copper finish and fabricator requirement before a new run.

## Checks and results

- A fresh nightly-KiCad XML export from the unchanged schematic matches all **12 component value/footprint pairs** and all **14 complete pin-connectivity groups** in the saved [netlist](../HallowBadges.net), allowing autogenerated unnamed-net labels to differ. VCC, GND, GPIO1 and GPIO2 names match exactly. All shared PCB pad groups match the fresh export. U1 pin 5 (`GPIO1`) drives R3 and Q1's gate; U1 pin 6 is `GPIO2`. There are no extra PCB-only electrical pads. The only schematic/netlist-only components are H1 and H2.
- Firmware pin mapping was checked against [MicroCore 2.5.2 pin definitions](https://github.com/MCUdude/MicroCore/blob/v2.5.2/avr/variants/attiny13a/pins_arduino.h), its [random-number APIs](https://github.com/MCUdude/MicroCore/blob/v2.5.2/avr/cores/microcore/WMath.cpp), and the [ATtiny13A datasheet](https://ww1.microchip.com/downloads/en/DeviceDoc/ATtiny13A-Data-Sheet-DS40002307A.pdf). PB0 / OC0A is physical pin 5; ADC3 is PB3, physical pin 2. J1 lacks the ISP RESET and SCK signals, so it must not be treated as an ISP header.
- Arduino CLI **1.5.1**, MicroCore **2.5.2**, AVR GCC **7.3.0**: the exact committed sketch compiles warning-free with `MicroCore:avr:13:clock=1M2,BOD=disabled,eeprom=keep,bootloader=no_bootloader`. Result: **706 / 1024 bytes flash; 4 / 64 bytes static SRAM**. The SRAM figure excludes runtime stack usage. No upload or fuse programming was performed; the original hardware clock/fuses remain unknown.
- KiCad CLI nightly **10.99.0**, temporary copies only, `pcb drc --format json --severity-all --exit-code-violations`: **32 → 29 violations**, consisting after the fixes of 14 cached-zone clearance errors, one artwork edge-clearance error, ten missing-standard-library configuration warnings and four silk-over-copper warnings. Both invalid-outline errors and the custom-library warning are gone. **Zero unconnected items** before and after.
- A separate temporary `--refill-zones` run removes all 14 cached-fill clearance errors. The old fills measure 0.5068–0.5073 mm against their 0.5080 mm zone clearance. The artwork edge error and fourteen warnings remain. The source fill and design rules were not rewritten, and nightly import explicitly warns that legacy fills are converted on a best-effort basis.
- Direct `sch erc --format json --severity-all --exit-code-violations HallowBadges.sch` now loads the unchanged legacy schematic and reports **26 findings** (exit 5): two `power_pin_not_driven` errors on U1 VCC/GND, twelve missing global symbol-library registration warnings and twelve missing footprint-library registration warnings. There are **no annotation errors**. The source battery symbol has passive pins and there are no PWR_FLAG markers, so ERC does not see a power-output driver. Power-marker annotations and global library registrations have not been added or the checks suppressed; this is not a clean ERC pass. `sch export netlist --format kicadxml` succeeds (exit 0).
- All nine [Gerber job](../gerber/HallowBadges-job.gbrjob) file references exist. The four original plated drill coordinates match the four PCB vias at the exported 0.0001-inch precision; the non-plated drill file contains no holes. Copper/silkscreen Gerbers were not geometrically regenerated or independently qualified.
- The [historical Gerbers, drill files](../gerber/), schematic PDF, netlist and BOM are retained unchanged. Source-outline cleanup has no nonzero contour change, but the exports are historical records rather than a newly validated release. Resolve the findings and regenerate/review outputs before manufacturing.
- Local documentation links, canonical existing CC BY-SA 4.0 text, generated-state ignore behavior and `git diff --check` pass.

## Limits

No physical measurements, battery-runtime retest, assembly validation, hardware programming, stable KiCad 5 ERC/DRC, complete fabrication equivalence or modern-KiCad migration was performed. Missing component values, original fuses and design intent cannot be recovered reliably from the committed evidence. The existing CC BY-SA 4.0 licence and third-party rights remain unchanged.
